# ADR 0005 — The OCR tier runs the engines directly, per page

**Status:** accepted (Phase 12.1)

## Context

Phase 07 refused a document with no text layer, with `error_code: "needs_ocr"`.
That was the right call — a standard-tier parse of a scan returns almost
nothing, and a chat built on almost nothing answers confidently out of an empty
document — and it was never meant to be permanent. Real corpora are dominated by
scanned agreements, stamped receipts and mixed filings.

Phase 12.1 has to make those documents readable while keeping four things that
were already true: one coordinate convention, a default build that is cleanly
Apache-2.0, `OFFLINE_MODE` as a guarantee rather than an aspiration, and a
refusal to parse a document into silence.

Three decisions follow, and each had a plausible alternative.

## Decision 1: tier per page, not per document

`inspect.py` already measured extractable-character density per page and then
collapsed the answer into one verdict about the document. Phase 12.1 stops
collapsing it. Every page gets a `PageTier`; Docling reads the native pages and
the OCR tier reads the scanned ones.

The alternative — one tier for the whole document — is what the code already
did, and it is wrong in both directions on the same corpus. A hundred-page
filing with three scanned exhibits either runs a recogniser over a hundred pages
to read three, or refuses a document that is 97% readable. Neither is defensible
once the recogniser exists, and the measurement that distinguishes them was
already being taken.

The tier is stored on `pages.tier` rather than derived at read time, because it
is a fact about how a particular parse was produced and the parse is cached.

## Decision 2: run RapidOCR and Tesseract directly, not through Docling

Docling can drive both engines. It was not used for this, and the reason is
narrow: the three things Phase 12.1 has to produce do not survive Docling's text
cell abstraction.

- **Per-page confidence.** The whole of the confidence-surfacing criterion, and
  the input to the fallback rule. Docling exposes recognised text and geometry;
  it does not carry the recogniser's own score per token up to where a caller
  can aggregate it.
- **The deskew transform.** Recognition happens on a straightened page and
  storage happens on the page as it exists. The inverse map between the two has
  to be held by whatever rotated the bitmap. Handing Docling a pre-deskewed
  image means handing it an image whose coordinates no longer describe the
  document.
- **Word-level boxes with their offsets.** Kept so that a citation can be
  tighter than a paragraph.

There is a real cost to this, and it should be named rather than glossed: the
OCR tier has **no layout model**. It emits paragraphs and nothing else — no
headings, no `sectionPath`, no table structure. Guessing structure from type
size would put claims about a document's shape onto every chunk of every scanned
document, and a wrong section path is worse than an absent one because it is
asserted rather than missing. Scanned-table reconstruction is Phase 12.2 and a
VLM reading of a page is Phase 12.3; both replace this, and neither is blocked
by it.

Docling still runs, unchanged, over the born-digital pages of the same document.
`ParseArtifact` is what makes that possible: the two tiers meet in the artifact
and nowhere else.

## Decision 3: RapidOCR primary, Tesseract fallback, both permissive

The default image must be Apache-2.0 compatible, so the strongest candidates
were excluded on licensing before accuracy was considered: PyMuPDF renders PDFs
beautifully and Marker is the best scanned-document pipeline available, and both
are AGPL. They belong behind the `advanced` Compose profile.

Of what remains, RapidOCR is primary because it runs PP-OCRv4 as ONNX graphs on
the CPU with the weights **inside the wheel** — no CUDA, no model download at
first use, no artifacts directory to bake into an image. That last property is
the same one `DOCLING_ARTIFACTS_PATH` buys for Docling, and it is what keeps
`OFFLINE_MODE` true of a machine that has never had a network.

Tesseract is the fallback because it is a genuinely different family of
recogniser — an LSTM over binarised connected components rather than a detector
plus a CRNN — so it fails on different pages. A fallback that failed on the same
pages would be latency with no information in it. It needs a system binary; the
default image ships one, and a deployment without one keeps working with the
primary engine alone.

The fallback is taken **only when it scores higher**. An engine reached because
the primary was unsure, which then does worse, has told us something about the
page rather than about the primary, and overwriting a 0.60 reading with a 0.31
one because the fallback happened to run second is the wrong reading of that.

## Consequences

- A scanned PDF that Phase 07 refused now reaches `ready`.
- `OCR_ENABLED=false` restores the Phase 07 refusal exactly, which is what a
  deployment that would rather see an error than a machine's reading of a
  photocopy should set.
- A document where recognition runs and finds nothing is still refused, with
  `needs_ocr` and a message naming the likely causes. The invariant is "never
  parsed into silence", and a recogniser reading a blank page does not change
  what silence is.
- Chunks from a scanned page carry no `sectionPath`. Retrieval over a scanned
  corpus is therefore slightly weaker than over a born-digital one, and the
  chunk header says less. This is the cost of decision 2 and it is paid back by
  Phase 12.3.
- A 500-page scanned document will exceed `WORKER_JOB_TIMEOUT_SECONDS` and be
  retried and eventually dead-lettered. That is a known gap; resumable
  checkpointing for very large documents is Phase 12.4's scope, and adding a
  page ceiling here would be a second, worse answer to the same question.

## What would make us revisit this

- Docling exposing per-token confidence and letting a caller supply a
  pre-processed page image along with the transform that produced it. Decision 2
  would then have no argument behind it.
- A permissively-licensed layout model that works on recognised text. That would
  let the OCR tier emit headings and section paths, which is the one real thing
  it currently gives up.
