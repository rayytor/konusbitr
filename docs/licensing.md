# Licensing

Konusbitr is Apache-2.0, and **the default build is cleanly Apache-2.0
compatible**. That is a promise about what `docker compose up` installs, not an
aspiration about what we would prefer, and it is enforced by a test that audits
the *installed environment* on every CI run.

This document says what is in the default build, what is deliberately kept out
of it, how the boundary is enforced, and what changes if you cross it.

---

## Why this is a hard constraint rather than a preference

The strongest document-processing libraries in Python are copyleft or
commercially restricted. PyMuPDF renders and extracts better than anything else
available and is AGPL-3.0. Surya's layout and reading-order models are GPL-3.0.
Marker is the best scanned-document pipeline in the open and carries a
commercial-use restriction.

Konusbitr is meant to be **self-hosted inside organizations that have lawyers**,
and a permissive default is the difference between "deploy it" and "open a
review". The AGPL in particular is not merely a copyleft licence — it reaches
network use, so a company running a patched Konusbitr for its own staff over
HTTP would be obliged to publish those patches. That is a perfectly reasonable
bargain for somebody to *choose*. It is not a bargain anybody should be
enrolled in by a transitive dependency.

So the rule is: the default image contains no AGPL, GPL, SSPL, Commons Clause
or non-commercial package, transitively included ones especially. The advanced
parsers exist, they are supported, and they are behind a switch you have to
throw yourself.

## The default build

Everything below is Apache-2.0, MIT or BSD-3, and all of it is installed by
`uv sync` in `services/worker` and baked into `docker/worker.Dockerfile`.

### The document pipeline

| Package | Licence | What it does |
| --- | --- | --- |
| `pypdfium2` | Apache-2.0 / BSD-3 | Page structure, rasterisation, thumbnails, the text layer, image objects |
| `docling` | MIT | Layout-aware parsing of born-digital pages, with boxes and reading order |
| `rapidocr-onnxruntime` | Apache-2.0 | PP-OCRv4 detection and recognition, weights shipped in the wheel |
| `onnxruntime` | MIT | The inference runtime the above runs on |
| `pytesseract` | Apache-2.0 | Wrapper around the Tesseract binary (Apache-2.0), the OCR fallback and the primary for shaped scripts |
| `opencv-python-headless` | Apache-2.0 | Deskew, denoise, binarise, ruling-line detection |
| `deskew` | MIT | The skew angle estimate |
| `pillow` | MIT-CMU | Image encoding, resampling, the figure and page images |
| `fast-langdetect` | MIT | Per-document language identification, FastText model inside the wheel |
| `torch`, `torchvision` | BSD-3 | Docling's layout models (CPU wheels only — see `pyproject.toml`) |

### The rest of the worker

| Package | Licence | What it does |
| --- | --- | --- |
| `litellm` | MIT | The one model router. No provider SDK is imported anywhere |
| `fastapi`, `uvicorn`, `uvloop` | MIT / BSD-3 | `/health`, `/ready`, the event loop |
| `redis` | MIT | The job stream |
| `asyncpg` | Apache-2.0 | The worker's own raw SQL |
| `boto3` | Apache-2.0 | S3-compatible storage |
| `pydantic-settings` | MIT | The environment contract |

### The product surface

Node dependencies are audited separately by `pnpm audit:licenses`. The
significant ones — Next.js (MIT), React (MIT), Drizzle (Apache-2.0), Better Auth
(MIT), Zod (MIT), `pdfjs-dist` (Apache-2.0), Tailwind (MIT), shadcn/ui (MIT) —
are permissive, and the audit refuses anything that is not.

### Fonts and fixtures

Instrument Serif and LINE Seed JP are SIL Open Font License 1.1. The fixture
fonts under `fixtures/fonts/` are subset by
`scripts/vendor-fixture-fonts.py` from OFL and Apache-2.0 sources and are
committed so regeneration does not depend on what a machine happens to have
installed. Every PDF under `fixtures/pdf/` is generated by `fixtures/generate.py`
— nothing is scraped, so no fixture carries somebody else's copyright.

## The `advanced` profile

Pinned in `docker/advanced-requirements.txt` and installed by one Dockerfile
stage.

| Package | Licence | Why it is quarantined |
| --- | --- | --- |
| `pymupdf` | **AGPL-3.0** (or a paid commercial licence) | Network copyleft: running a modified Konusbitr as a service obliges you to publish the modifications |
| `surya-ocr` | **GPL-3.0** | Copyleft on distribution |
| `marker-pdf` | **GPL-3.0**, with a commercial restriction on the hosted weights | Copyleft *and* a use restriction that is not an open-source licence at all — so it is not installed even here; see below |

### Why they are a requirements file and not a `pyproject.toml` extra

This was an extra first, and it could not stay one. Both packages pin
`pillow<11`; `pillow>=11` is a **runtime dependency of the default build**; and
uv resolves a project's extras together with its base dependencies, so one
lockfile can describe every installable combination.

The result was that the default resolution became unsatisfiable, and the only
ways out would have been to downgrade Pillow in the Apache-2.0 image or to
loosen its pin. Either way, an optional, quarantined, never-installed package
would have decided what the image everybody runs actually ships.

That is the quarantine leaking in the one direction it must never leak. So the
advanced packages sit entirely outside the project's resolution — pinned in
`docker/advanced-requirements.txt`, installed by the `worker-advanced` stage and
by nothing else. `uv lock --check` plus a grep over `uv.lock` is the CI
assertion that they stayed there.

Marker is absent even from that file. It is GPL-3.0 *and* carries a
commercial-use restriction on its hosted weights, which is not an open-source
licence but a use restriction an operator has to evaluate against their own
situation — and it fetches a large model set at first use, which would make the
advanced image a network dependency in a project whose `OFFLINE_MODE` is a
headline claim. Install it yourself if you want it, and accept both.

### What installing them changes

Building `worker-advanced` produces an image whose effective licence is the
strongest copyleft inside it — AGPL-3.0 with PyMuPDF present. **You may not
redistribute that image under Apache-2.0.** For internal use inside one
organization this mostly does not bite; for anything you ship, host for others,
or resell, read the licences themselves rather than this paragraph.

Konusbitr's own source stays Apache-2.0 either way. What changes is the licence
of the *combination* you built.

### How to build it

```bash
docker build \
  -f docker/worker.Dockerfile \
  --target worker-advanced \
  --build-arg ENABLE_ADVANCED_PARSERS=true \
  -t konusbitr-worker:advanced .
```

or, through Compose, which builds exactly that target:

```bash
docker compose --profile advanced up
```

The `advanced` profile replaces the default `worker` service with
`worker-advanced`, built from a later stage of the same Dockerfile. It
**replaces** rather than joins: both consume the same Redis consumer group, so
leaving the default worker running would split jobs between an image that has
these parsers and one that does not, and a document would then be parsed
differently depending on which container claimed it. Hence `WORKER_REPLICAS=0`.

Nothing about the default profile changes, and nothing about the default image
contains these packages — this is a separate build target, not a runtime flag.

The stage **fails the build** without `ENABLE_ADVANCED_PARSERS=true` rather than
quietly producing an image identical to the default one. A silent no-op would
let somebody target the stage, get a clean image, believe they had the advanced
parsers, and find out at the first document that they did not.

### What you get for it

Honest answer: today, not much that the default build cannot do. The Phase 12.1
and 12.2 OCR tier reads scans, languages, ruled tables and figures on entirely
permissive software, and Phase 12.3's VLM tier gets structure and reading order
from a vision model rather than from a GPL layout model. The profile exists
because the packages are genuinely better at a handful of things — PyMuPDF's
extraction on adversarial PDFs, Surya's reading order without a model call —
and because an operator who has already accepted the AGPL should not have to
fork the project to use them.

`konusbitr_worker.parse.advanced` is where they are reached, and it is written
so that a default build reports their absence rather than failing: nothing
imports them at module scope, and every entry point answers "not installed"
cleanly.

## How the boundary is enforced

Three mechanisms, at three different moments, because any one of them alone has
a gap.

### 1. A test over the installed environment

`services/worker/tests/test_licensing.py` runs `pip-licenses` over the
environment it is executing in and fails on any package declaring AGPL, GPL,
SSPL, Commons Clause or a non-commercial restriction. It also fails on any
package whose declared licence it cannot place at all, which is what catches a
new transitive dependency that spells its licence in a way nobody anticipated.

It is a **test**, not a CI-only script, on purpose: a branch that adds a
dependency which quietly changes the licensing of the default build should fail
on the machine where it was added, before it reaches anybody else.

It audits the installed environment rather than the lockfile because that is
where the answer is. A restrictively-licensed package almost always arrives as
somebody else's transitive dependency, and that becomes visible at install time
and not at resolve time.

### 2. `pnpm audit:licenses`

One command that runs both halves — the Python audit above and an equivalent
sweep over the Node dependency tree — and prints what it found. CI runs it; so
can you, before opening a pull request:

```bash
pnpm audit:licenses
```

### 3. Build and Compose isolation

The default `docker/worker.Dockerfile` target installs `uv sync --no-dev` from
`uv.lock` and nothing else, and that lockfile does not mention the advanced
packages at all. They are installed only by the `worker-advanced` stage, only
from `docker/advanced-requirements.txt`, and only when
`ENABLE_ADVANCED_PARSERS=true` is passed — without it the stage exits with an
error. In `docker-compose.yml` that stage is reachable only under
`profiles: [advanced]`.

So there are three independent locks: the packages are not in the project's
resolution, the stage that installs them refuses to build unasked, and it is not
in the default profile.

## Adding a dependency

1. Check its licence, and check what it drags in. `uv add --dry-run` then
   `uv run pytest tests/test_licensing.py` is the fast loop.
2. If the audit cannot place the licence and the package is genuinely
   permissive, add its spelling to `ALLOWED` in the test, or the package to
   `KNOWN_GOOD` with a note saying where the answer came from. Keep that list
   short — it is the part of this system that can rot.
3. If it is AGPL, GPL or restricted: it goes in
   `docker/advanced-requirements.txt` — never in `pyproject.toml`, not even as
   an extra — it is imported through `konusbitr_worker.parse.advanced`, and it
   gets a row in the table above.

There is no fourth option. A restrictively-licensed package in the default build
is not a trade-off to weigh against a feature; it breaks the promise this
document exists to keep.
