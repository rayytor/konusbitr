# Phase 12.2/4 — Multilingual Routing, Table Extraction & Figure/Image Extraction

**Goal:** extend Konusbitr to handle non-Latin and multilingual documents (CJK, Arabic, Turkish, Cyrillic), accurately parse complex tables from scanned pages into dual Markdown and JSON formats, and extract embedded figures with semantic AI captioning indexed for vector retrieval.

## Context

Phase 12.1/4 established the permissive CPU OCR foundation for standard Latin-script scans. However:
1. Global organizations ingest contracts and reports in Turkish, Arabic, Japanese, Chinese, and mixed languages. Blindly running English OCR on Arabic or Japanese produces unindexable garbage.
2. Scanned financial statements, clinical reports, and invoices contain dense tabular grids. Flattening a scanned table into unstructured text destroys semantic row/column associations and prevents cell-accurate citations.
3. Image-heavy PDFs (presentations, research papers, earnings reports) encode critical knowledge in charts, plots, and architecture diagrams. Unless extracted, stored, and captioned, visual knowledge remains completely invisible to hybrid search.

## Scope

### 1. Language Detection & Multilingual OCR Dispatch

Handling multi-language documents follows a deterministic precedence hierarchy:

```
settings.langList provided?
  ├── YES ──► Normalize BCP-47 tags ──► Load model dictionaries ──► Run Multilingual OCR
  └── NO  ──► Extract text/sample snippet ──► fast-langdetect ──► Auto-dispatch engine
```

#### Language Auto-Detection
When `settings.langList` is empty (the default in `ParseSettingsSchema`), run ultra-fast language identification:
- Use `fast-langdetect` (80x faster than `langdetect`, based on FastText, MIT-licensed) on any initial extracted text or low-confidence preliminary OCR pass.
- Identify the top primary script / language candidates (e.g. `['tr']`, `['zh', 'en']`, `['ar']`).

#### Engine Dispatch & Script Routing
- **RapidOCR Dictionaries:** RapidOCR ships specialized lightweight ONNX recognition models for Chinese, English, Japanese, Korean, Latin, and Cyrillic. Dispatch the appropriate model weight based on detected tags.
- **Tesseract Language Packs:** For languages with complex contextual shaping (Arabic, Devanagari, Hebrew) or specific national alphabets (Turkish, Vietnamese), invoke Tesseract with language packs (`ara`, `tur`, `heb`, `hin`).
- **Reading Order:** Preserve bidirectional text flow for Right-to-Left (RTL) scripts (Arabic, Hebrew) so that text sequences inside bounding boxes remain logically coherent.

### 2. Table Recognition & Extraction on Scanned Pages

Born-digital PDFs in Phase 07 extracted tables using Docling's native layout models. For scanned pages, this sub-phase introduces optical table structure decomposition:

```
Scanned Page Image
  ├──► Table Detection (detect bounding box of table area)
  ├──► Structure Recognition (Docling TableFormer / RapidOCR Table Structure)
  │      └── Predict row/column grids, merged cells, headers
  └──► Text Assignment (map word OCR boxes into specific table cells)
```

#### Dual Output Artifact Format
As specified in Phase 07, table data is preserved in two representations:
1. **Markdown Format:** Rendered as standard GitHub Flavored Markdown inside `parse_results.markdown` so chat models receive natural tabular context during generation.
2. **Structured JSON Format:** Emitted inside `contents[].tableJson` with explicit column headers, row arrays, and cell-level bounding boxes:

```jsonc
{
  "id": "el_0104",
  "type": "table",
  "page": 4,
  "bbox": [54.0, 120.0, 550.0, 410.0],
  "markdown": "| Metric | Q3 2024 | Q3 2025 |\n|---|---|---|\n| Revenue | $12.4M | $18.2M |",
  "tableJson": {
    "numRows": 3,
    "numCols": 3,
    "headers": ["Metric", "Q3 2024", "Q3 2025"],
    "rows": [
      ["Revenue", "$12.4M", "$18.2M"],
      ["Net Income", "$2.1M", "$4.3M"]
    ],
    "cells": [
      { "rowIndex": 1, "colIndex": 0, "text": "Revenue", "bbox": [58.0, 160.0, 180.0, 180.0] }
    ]
  }
}
```

- **Chunking Invariant:** A table element is **never split** across chunks in Phase 08. The entire table structure is preserved as a single atomic retrieval chunk.

### 3. Embedded Image & Figure Extraction

Extract visual assets from the document and persist them to durable object storage:

- **Extraction Mechanics:** Scan PDF stream objects using `pypdfium2` and `pypdf` to extract raster bitmaps and vector graphic regions. Filter out decorative line rules, background gradients, and icons ($< 100 \times 100$ pixels).
- **Storage Key Convention (`packages/storage`):**
  Images are saved to S3/MinIO under the deterministic key layout established in Phase 05:
  ```
  orgs/{orgId}/documents/{docId}/images/{n}.png
  ```
- **Parse Artifact Population:**
  Populate the `images[]` array in the parse result:
  ```typescript
  interface ExtractedImage {
    id: string;          // e.g. "img_001"
    page: number;        // 1-indexed page number
    bbox: [number, number, number, number]; // [x0, y0, x1, y1] in points
    width: number;       // pixel width
    height: number;      // pixel height
    storageKey: string;  // S3 object key
    caption: string | null;
  }
  ```

### 4. Semantic Figure Captioning (`llm: true`)

When ingestion is invoked with `settings.llm = true` (or via public API parameter `llm: true`):

1. **Vision Model Dispatch via LiteLLM:**
   - Filter extracted images for meaningful diagrams, plots, schematics, and charts.
   - Dispatch the image through the unified model router (`packages/ai`) using the configured `vision` role (e.g. Gemini 2.0 Flash, Claude 3.5 Sonnet, GPT-4o, or local Qwen2.5-VL).
   - Use versioned prompt `packages/ai/prompts/caption_figure_v1.txt`:
     > "Provide a dense, objective, 2-3 sentence factual description of this document figure. Detail axis labels, trends, percentages, entities, and key takeaways. Avoid preamble."
2. **Search Indexing Integration (Phase 08 Bridge):**
   - Attach the generated caption to the `ExtractedImage` object.
   - During chunking, synthesize a figure chunk:
     ```markdown
     [Figure: Q3 Revenue Breakdown by Region. North America accounts for 54% ($9.8M), Europe for 28% ($5.1M), APAC for 18% ($3.3M).]
     ```
   - This allows users to ask natural questions like *"Which region had the fastest growth in Q3?"* and retrieve the exact chart citation.

## Non-Goals for Phase 12.2/4

- End-to-end full page VLM parsing (`quality: "advanced"` is handled in Phase 12.3/4).
- Proprietary or AGPL engines like Marker or PyMuPDF (quarantined in Phase 12.3/4).
- Resumable job checkpoints across worker restarts (handled in Phase 12.4/4).
- Progress UI component refactoring in Next.js (handled in Phase 12.4/4).

## Acceptance Criteria

- [ ] **Multilingual Recognition:** A multi-page document containing Turkish, Arabic, and Chinese pages is accurately parsed when `langList` is specified, showing $\ge 90\%$ character recognition rate on evaluation fixtures.
- [ ] **Auto-Detection Reliability:** When `langList` is omitted, `fast-langdetect` correctly classifies the primary document language on foreign-language fixtures without user input.
- [ ] **RTL Script Coherence:** Arabic and Hebrew text maintains correct logical character sequence and reading order inside extracted paragraphs.
- [ ] **Scanned Table Decomposition:** A scanned financial balance sheet parses into valid Markdown table syntax and complete `tableJson` carrying row/column dimensions and header names.
- [ ] **Atomic Table Chunks:** Chunker unit tests verify that scanned tables are never split across chunk boundaries.
- [ ] **Image Storage Integrity:** Embedded images from PDF documents are extracted, converted to PNG/WebP, and persisted under `orgs/{orgId}/documents/{docId}/images/{n}.png` in MinIO/S3.
- [ ] **Figure Captioning & Searchability:** When `llm: true`, extracted diagrams receive factual captions via the vision router, and a hybrid search query for chart-specific terminology successfully retrieves the figure chunk.
