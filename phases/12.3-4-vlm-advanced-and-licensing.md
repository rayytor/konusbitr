# Phase 12.3/4 — Vision-Language Model (VLM) Advanced Pipeline & Licensing Isolation

**Goal:** implement the Tier 3 "advanced" VLM parsing path for complex layouts using frontier vision models (Qwen2.5-VL, Claude, GPT-4o, Gemini), hybrid reconciliation with exact text layers, pre-flight cost guardrails, and rigorous Apache-2.0 vs. AGPL licensing isolation.

## Context

Standard OCR engines excel at character recognition on clean lines, but frequently fail on **complex spatial layouts**: multi-column newsletters, magazine sidebars, flowcharts, overlapping text boxes, and dense mathematical notation.

Vision-Language Models (VLMs) process whole page images natively and understand visual hierarchy and reading order. However, VLMs introduce two significant operational hazards:
1. **Hallucination & Drift:** An ungrounded VLM may hallucinate digits, dates, or words.
2. **Cost & Latency:** High-resolution page inference across hundreds of pages can rapidly exhaust budgets.

Furthermore, popular document parsing packages like **PyMuPDF (AGPL-3.0)**, **Surya (GPL-3.0)**, and **Marker (non-commercial restrictions)** carry viral or commercially restrictive licenses. Konusbitr must maintain a **clean Apache-2.0 default build** while supporting advanced engines exclusively behind an optional, isolated profile.

## Scope

### 1. The VLM "Advanced" Ingestion Path (Tier 3)

The Tier 3 path is triggered when:
- The request explicitly specifies `settings.quality === "advanced"`, or
- An automated fallback occurs because OCR confidence or layout consistency on a complex page drops below `TIER_FALLBACK_THRESHOLD` (0.60).

```
Document Page (Rasterized @ 150–200 DPI via pypdfium2)
  │
  ▼
LiteLLM Vision Router (packages/ai)
  ├── Cloud: Claude 3.5/3.7 Sonnet | GPT-4o | Gemini 2.0/2.5 Flash
  └── Local/Offline: Qwen2.5-VL-7B-Instruct / 72B via Ollama / vLLM
  │
  ▼
Prompt (packages/ai/prompts/vlm_parse_v1.txt)
  └── Return structured Markdown + Element Bounding Boxes [ymin, xmin, ymax, xmax]
```

#### Prompt Specification
The vision model is called with a rigid JSON Schema output expectation:
```jsonc
{
  "elements": [
    {
      "type": "heading" | "paragraph" | "table" | "figure" | "callout",
      "level": 1, // for headings
      "text": "Exact text extracted from the block...",
      "markdown": "Markdown representation...",
      "bbox_normalized": [120, 45, 180, 520], // 0-1000 scale
      "reading_order": 1
    }
  ]
}
```

#### Local / Offline Model Integration
When `OFFLINE_MODE=true` is enabled, the vision router automatically directs requests to local `Qwen2.5-VL-7B-Instruct` served by the `local-llm` Ollama container or an optional vLLM service. It never touches public endpoints.

### 2. Hybrid Reconciliation (Structure + Text Layer Precision)

To prevent VLM hallucination (e.g., misreading financial numbers or contract dates), Konusbitr performs **hybrid reconciliation**:

```
       ┌────────────────────────┐         ┌────────────────────────┐
       │   Native PDF Text /    │         │      VLM Semantic      │
       │   High-Confidence OCR  │         │   Layout & Structure   │
       └───────────┬────────────┘         └───────────┬────────────┘
                   │                                  │
                   │ (Exact characters & coordinates) │ (Reading order, headings, tables)
                   ▼                                  ▼
             ┌──────────────────────────────────────────────┐
             │       Hybrid Reconciliation Engine           │
             │   - Aligns VLM structural blocks with tokens │
             │   - Replaces VLM text with exact font tokens │
             │   - Flags ungrounded text discrepancies     │
             └──────────────────────┬───────────────────────┘
                                    │
                                    ▼
                         Authoritative Parse Artifact
```

- **Exact String Invariant:** When native text or high-confidence OCR characters fall within a bounding box detected by the VLM, the verbatim character sequence from the text layer overrides the VLM's generated text.
- **Reading Order Invariant:** The VLM's structural flow dictates reading order, column sequence, and heading hierarchies, eliminating the multi-column reading order confusion common in standard extractors.

### 3. Cost Guardrails & Pre-flight Estimation

Running multi-page VLM inference is expensive. Strict guardrails prevent runaway bills:

1. **Pre-flight Estimation API:**
   - `POST /api/documents/estimate-cost`
   - Accepts document page count and `quality: "advanced"`.
   - Returns estimated tokens, processing latency, and estimated USD cost.
2. **UI Confirmation Modal:**
   - In `apps/web`, selecting `advanced` displays a confirmation showing the estimated credit/USD cost and asking for explicit confirmation before job submission.
3. **Hard System Limits:**
   - `MAX_VLM_PAGES_PER_JOB` (default 50 pages). Documents exceeding this limit fail fast with `error_code: "too_many_pages"`.
   - Per-organization monthly spend caps enforced at intake.

### 4. Licensing Discipline & Container Profile Isolation

Konusbitr adheres to uncompromising open-source licensing hygiene:

```
Default Build (Apache-2.0 Clean)
  ├── pypdfium2 (Apache-2.0 / BSD-3)
  ├── Docling (MIT)
  ├── RapidOCR / ONNX Runtime (Apache-2.0 / MIT)
  ├── Tesseract OCR (Apache-2.0)
  ├── OpenCV Headless (Apache-2.0)
  └── Fast-Langdetect (MIT)

Optional Compose Profile: "advanced"
  ├── PyMuPDF (AGPL-3.0) ── Quarantined behind COMPOSE_PROFILES=advanced
  ├── Surya / docling-surya (GPL-3.0) ── Quarantined behind build flag
  └── Marker (Non-commercial license) ── Quarantined behind build flag
```

#### Technical Isolation Mechanics
1. **Docker Build Target:** Default `docker/worker.Dockerfile` contains zero AGPL/GPL packages. A secondary build stage `worker-advanced` is triggered only when `--build-arg ENABLE_ADVANCED_PARSERS=true` is passed.
2. **Compose Separation:** In `docker-compose.yml`, advanced parsers run only under `profiles: [advanced]`.
3. **Documentation:** Create `docs/licensing.md` detailing every package, its license, and the boundary separating the permissive core from optional profiles.
4. **Automated CI Gate:** A CI workflow runs `pip-licenses` and fails if any AGPL, GPL, or non-commercial license is present in the standard build:
   ```bash
   pnpm audit:licenses
   ```

## Non-Goals for Phase 12.3/4

- Making the AGPL or non-commercial parsers part of the default Docker container.
- Unlimited, unmetered VLM processing on documents exceeding 50 pages.
- Resumable job checkpointing across worker crashes (handled in Phase 12.4/4).

## Acceptance Criteria

- [ ] **VLM Advanced Parsing:** A multi-column magazine or complex brochure parsed with `quality: "advanced"` exhibits superior heading hierarchy, reading order, and table layout compared to standard extraction.
- [ ] **Hybrid Reconciliation Precision:** Numbers, dates, and legal names in the reconciled parse artifact match the native PDF text layer verbatim ($\ge 99.9\%$ string identity), eliminating VLM hallucination.
- [ ] **Offline VLM Functionality:** With `OFFLINE_MODE=true`, `quality: "advanced"` routes successfully to local `Qwen2.5-VL` without attempting any outbound network traffic.
- [ ] **Cost Guardrails:** Documents exceeding `MAX_VLM_PAGES_PER_JOB` are rejected at intake with `error_code: "too_many_pages"`. `POST /api/documents/estimate-cost` provides accurate estimates prior to upload.
- [ ] **Clean Apache-2.0 Default Build:** The default worker container image contains zero AGPL or GPL dependencies, verified by an automated CI step running `pip-licenses`.
- [ ] **Licensing Documentation:** `docs/licensing.md` exists, detailing all licenses and the usage conditions for the `advanced` profile.
